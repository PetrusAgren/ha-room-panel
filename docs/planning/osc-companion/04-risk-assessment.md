# Risk assessment

Risk assessment for the baseline in [research](01-research.md). Severity and likelihood are engineering estimates before a physical pilot. Critical means potential unintended audio change or broad control access. High means lost control, corrupted configuration or misleading state. Medium means degraded performance or operational friction. Proposed mitigations are requirements for feature implementation, and do not imply that failures have been observed in production.

| ID | Risk, cause and affected code | Severity | Likelihood | Mitigation | Verification |
| --- | --- | --- | --- | --- | --- |
| R01 | A new fader ceiling is bypassed by legacy command or preset apply. control.player_command and control.apply currently send numeric HA calls directly. | Critical | High | Common canonical target policy covers every Room Panel write origin. Treat opaque scripts/scenes separately. | Enumerate HTTP, admin, preset and event paths. Forge an oversized value on each. |
| R02 | A cached level is resent on recovery after the physical console has changed. New provider startup may wrongly treat stored state as intent. | Critical | Medium | Read-on-connect, increment generation, discard queued motion and never replay persisted levels. | Restart app/device/network with physical/simulated level changed. Assert zero writes. |
| R03 | Numeric units or fader law are wrong, turning a small UI movement into a large audio change. New mapping/profile code affects current volume behavior. | Critical | Medium | Separate canonical units from wire values, version verified curves and test endpoints/unity gain. | Golden fixtures, property tests and safe real-device qualification. |
| R04 | UDP replies use a source port changed by container NAT or VirtualBox topology. Current config.yaml has no OSC mappings. | High | High | Bind/send/receive same socket when needed, test UDP slots, document host-network variant only where necessary. | Packet capture from HAOS and target, fixed-port and source-reply tests. |
| R05 | Concurrent panel operators overwrite each other. Current command route has no gesture ownership. | High | High | Canonical-target leases, scoped sequence numbers, busy UI and bounded expiry. | Two simultaneous drags, late requests from losing gesture, two sessions targeting one device. |
| R06 | Feedback snaps the active thumb or suppresses unrelated updates. panel.js rewrites section HTML and suppresses all section rendering during a drag. | High | High | Stable keyed range nodes and per-control gesture/observed state. | Drag A while feedback changes B, then release/cancel A. |
| R07 | Request backlog sends old levels after the operator stops. Input can exceed HTTP/device throughput. | High | High | Latest-value pending slot, per-target in-flight send, final priority and cancellation discard. | Slow provider under burst input, assert output order and queue bounds. |
| R08 | Out-of-order OSC feedback is interpreted as a new command confirmation. OSC may carry no timestamp/sequence. | High | Medium | Keep observed uncertainty, profile query/settling policy and no feedback-triggered writes. | Delay/reorder packets and compare actual target state with UI quality. |
| R09 | Write-only hardware appears connected/confirmed because UDP send succeeds. Existing UI's single connected flag is HA-specific. | High | High | Per-provider evidence, commanded/observed/stale quality and explicit write-only status. | Drop all replies while accepting sends. |
| R10 | Expired feedback subscriptions leave an apparently live value. New OSC profiles need renewals and freshness. | High | Medium | Profile-specific renewals, monotonic deadlines, bounded read recovery and diagnostics. | Expire subscription and interrupt renewals while sockets remain open. |
| R11 | HA disconnect disables healthy OSC controls. Current panel.js command/render depend on state.connected. | High | High | Preserve aggregate status for compatibility, add per-control availability and independent provider tasks. | Disconnect Core while dragging a qualified OSC control. |
| R12 | HA event loss causes stale authoritative values. ha._reader logs and drops when its 512-event queue is full. | High | Medium | Mark affected HA state stale and reload snapshot after overflow. | Flood queue and assert resync before fresh quality. |
| R13 | Automatic room selection fails when label ID differs from label name. ha._load_snapshot turns IDs into names, while profile_entities compares label_id. | High | High for differing IDs | Preserve IDs and names separately, maintain compatible public display data. | Rename label and use ID/name-different fixture. |
| R14 | Opaque Companion macro or HA scene exceeds a room fader ceiling. Macro may affect multiple parameters outside coordinator. | Critical | Medium | Document scope, require review for restricted controls, use direct validated parameter actions where guarantees are needed. | Test macro that changes a second parameter. Verify UI does not promise enforcement. |
| R15 | Companion API capability is assumed from a nominal version, breaking feedback or data types. app image 5.1.3 differs from newest Satellite features. | High | Medium | BEGIN/CAPS negotiation, deployed OpenAPI inspection and explicit older fallback. | Fake old/new server, absent CAPS, strings versus typed variables. |
| R16 | Stuck hold action after lost release. Browser cancellation, app crash or network loss interrupts down/up lifecycle. | Critical | Medium | Atomic press first, deliberate qualified hold controls with short leases and best-effort release. Exclude critical hold actions without a safe device behavior. | Disconnect after down and verify actual release/failsafe. |
| R17 | Companion color feedback is mistaken for a physical boolean or level. UI-derived state may be ambiguous. | High | Medium | Mark Companion visual state separately and use verified module variables for numeric observation. | Same color for two device states, stale module variable and unknown value. |
| R18 | A Companion page edit moves/deletes a configured action. Bindings use locations and imports may become stale. | High | Medium | Import revision/checksum, broken-target indication and explicit rebinding with preview. | Move a button and re-import without creating duplicate controls. |
| R19 | Forged requests gain arbitrary OSC destinations or cross-room state. New APIs or SSE may skip authorize filtering. | Critical | Medium | Fixed backend bindings, admin-only connections/policies, per-request scoping and reauthorization of streams. | Door/cross-room/revoked sessions, forged host/address and hostile Origin. |
| R20 | Legacy OSC/Companion network listeners expose controls to untrusted LAN clients. UI PIN does not protect these transports. | Critical | Medium | AV network ACLs, minimal published ports and least-privilege v2 API keys. UDP source filters are defense in depth. | Scan from guest and AV networks, check bypass paths and redaction. |
| R21 | Crafted OSC data or profile import blocks the app event loop. Recursive bundles, timetags, broad patterns or unbounded tasks cause overload. | High | Medium | Packet/depth/pattern/task limits, immediate-bundle subset and typed declarative imports. | Fuzz malformed/oversized/future bundles while measuring HTTP responsiveness. |
| R22 | App/settings corruption or concurrent edits lose room bindings. Store uses autocommit JSON records with no schema migration/CAS. | High | Medium | Explicit transactions, schema version, revision guards and consistent backup. | Kill during save/migration, concurrent PUT and backup/restore. |
| R23 | A new profile revision silently changes output meaning. Normalized units or channel indices vary across products/firmware. | Critical | Medium | Pin profile revision/hash, explicit diff/migration and retained prior version. | Upgrade a conversion curve and verify no automatic rebinding/write. |
| R24 | External level exceeds panel range and a feedback clamp changes the physical device unexpectedly. | Critical | Medium | Preserve raw observed value, clamp thumb only, show warning and deliberate pickup. | Set above ceiling externally, open/reload panel, assert zero writes until gesture. |
| R25 | Optional HA export creates a state/command loop or replays retained levels. Exported entities can be rediscovered by current HA path. | Critical | Medium | Single write owner, origin identity exclusion, non-retained commands and fresh generation checks. | Broker/Core/app restarts and discover an exported parameter. |
| R26 | iPad pointer, focus or rendering behavior differs from desktop. Current native range/change behavior is insufficient for continuous control. | Medium | High | Touch/keyboard tests on target Safari, stable nodes, pointer capture and visibility handling. | Browser/home-screen modes, screen rotation, lost capture and keyboard-only use. |
| R27 | Co-hosted Companion consumes resources or crashes during a busy event. No host performance data has been measured. | High | Medium | Separate HA app lifecycle, bounded Room Panel rates, measure actual module load and recovery. | Thirty-minute loaded VM run with restart and independent provider failure. |
| R28 | Backup rollback combines an old app with new schema or misses WAL/Companion state. | High | Medium | Matched app/database bundle, cold or SQLite-consistent backup, independent Companion export. | Restore into clean VM and exercise old/new panels and presets. |
| R29 | Pairing links remain reusable before redemption longer than intended. Store records created time but redemption omits expiry check. | High | Medium | Enforce documented TTL, retain single-use transaction and test boundaries. | Expired, replayed and concurrent redemptions. |

## Ownership and release gates

The implementation owner signs off R01–R03, R05–R09 and R22–R25 with automated contract tests. The HA packaging owner qualifies R04, R20, R27 and R28 on the intended VM. The profile author qualifies device feedback, laws and renewal behavior. The frontend owner verifies R06/R26 on a real iPad. These are proposed work responsibilities, not claims that separate people have accepted assignments.

The first audio pilot requires policy-path tests, no-write-on-reconnect evidence, working device feedback/quality indicators and a tested restore. Exact equipment model, firmware and networking support remain open until recorded in Phase 0. Generic write-only OSC remains available with honest commanded quality, while safety-sensitive level control needs a qualified profile and operational review.
